# 업그레이드 노트

운영 중인 서버를 새 릴리스로 올릴 때 **운영자가 알아야 하거나 직접 해야 하는 일**을 릴리스별로 적는다. 무엇이 바뀌었는지는 [CHANGELOG.md](../../CHANGELOG.md), 평소 업데이트 절차는 [deploy-ubuntu.md](../deploy-ubuntu.md)·[deploy-systemd.md](../deploy-systemd.md)·[deploy-k3s.md](../deploy-k3s.md), 릴리스를 만드는 절차는 [runbook.md "릴리스 만들기"](../runbook.md#릴리스-만들기)에 있다.

| 릴리스 | 노트 | 내용 |
|---|---|---|
| 1.5.0 | [folder-tools-transfers.md](folder-tools-transfers.md) | 순번 정리·중복 찾기·파일별 전송 진행률. `Node.modifiedAt`·`takenAt` 컬럼 추가와 기존 파일 백필(자동) |

노트가 없는 릴리스는 `git pull` 뒤 릴리스 스크립트만 실행하면 된다.

## 언제 쓰나

아래 중 하나라도 해당하는 릴리스는 노트를 쓴다.

- DB 스키마나 데이터 마이그레이션이 오래 걸리거나, 끝났는지 확인이 필요하다.
- SSD의 디렉터리 레이아웃이 바뀐다(`storage:migrate`).
- `.env`에 새 값이 필요하거나 기본값의 의미가 바뀐다.
- Nginx·systemd·k3s 템플릿을 다시 적용해야 한다.
- 릴리스 뒤에 한 번 실행할 명령이 있다(백필, 다시 만들기 등).
- 이전 릴리스로 되돌릴 때 주의할 점이 있다.

## 파일 이름과 틀

새 노트는 `docs/upgrade/v<버전>.md`로 만들고 위 표 맨 위에 올린다. 구성은 아래 순서를 따른다(해당 없는 절은 "없음"이라고 적는다).

0. **이번 버전에서 바뀌는 것** — DB 스키마, DB 데이터, SSD, Redis, `.env`, Nginx, 이미지, 브라우저를 표로 적고 자동으로 처리되는지 직접 해야 하는지 나눈다.
1. **실행 전 점검** — 지금 버전 기록, 백업, 여유 공간.
2. **새 코드 받기**
3. **릴리스 실행** — 걸리는 시간, 백필이 있다면 진행 확인 방법.
4. **적용 확인** — 서버, DB, 화면.
5. **새 기능 사용법과 주의점** — 한도와 그것을 바꾸는 env.
6. **문제가 생겼을 때**
7. **롤백** — 스키마가 expand 단계라 이전 릴리스가 그대로 동작하는지, 아니면 백업 복구가 필요한지.
8. **systemd / k3s** — Docker와 다른 점.
